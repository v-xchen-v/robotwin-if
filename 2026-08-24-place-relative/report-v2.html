TL;DR

做了什么

把 place_relative 从「关系二选一（beside/on-top，且两关系场景不同）」重写为 五方位单场景：左右前后上，同一场景跑 5 条指令。

怎么验证

Layer B teleport 判定 23/23（含全部错方位反例 + 错参照 + 同场景结构）；oracle 逐方位成功率 95%（left 92 / right 100 / front 83 / back 100 / on-top 100）；真实采集 8/8、0 fail，5 段视频逐方位复核。

结论

方位词是唯一被打分的轴。scene_seed=seed//5 定场景、seed%5 定方位 → 连续 5 个种子是像素级同一场景、只有 {D} 方位短语不同；判定改成带符号轴偏移 + 正交轴锁死。

最大的坑

① 「前」(+y) 一开始规划不出来——实测可达带只有 y∈[−0.28,−0.01]，B 太靠前把「前」目标顶到不可达的 +y；把 B 往里挪、offset 收到 0.11 后解决。 ② 侧向抓取跨身体失败——抓必须用 mover 侧手臂，不是目标侧。

背景与目标：为什么要改 v1

v1（见 v1 报告）已经能测「beside vs on-top」，但它有两个和 IF-Ext §6「单轴诊断」定位不合的地方：

  • 只有 2 个方位，覆盖不了「左/右/前/后」这套完整相对方位轴；
  • 两关系的场景其实不同（干扰物数量由混合种子决定、每关系一套），没有做到「同一帧只变指令」——而 IF 实现 SOP 明确要求单轴任务必须让场景在所有 mode 值上逐像素相同， policy 唯一能区分的只能是指令。参照 laptop_verb（{V}）/ grasp_cube_approach（{D}）已落地的同场景配对范式。

本次目标：把 beside 拆成 左/右/前/后 四个带符号方位 + 保留 上 = 5 方位；判定逻辑跟着改成方向性； 减少干扰物腾空间；让 5 个方位共用一个初始场景，只有指令不同。

判定正反例（Layer B，teleport 驱动 23/23）

正例只证「做对→True」，不证「做错→False」。用 teleport 直接摆末态、断言布尔值，覆盖：

  • ✓ 5 方位正例各自 True；空操作（没动）5 方位全 False。
  • ✗ 错方位反例（关键）：该左却放右 → False；该前却放后 → False；侧向却叠在顶上 → False；该上却放旁边 → False。
  • ✗ 错参照：方位对但相对干扰物而非 B → False。
  • ✓ 结构：连续 5 元组同一场景（A/B/干扰物位姿一致）、方位按序循环 [左,右,前,后,上]。

关键决策 / 教训

坑 ①「前」(+y) 规划不出来 → 实测可达带，把 B 往里挪 + offset 收窄
首轮 oracle 前=0%：plan_ok=False，手臂根本够不到 +y。探针实测可达放置带只有 y∈[−0.28,−0.01]（+y 在机器人身后不可达）。 原 B 在 y≈−0.07 太靠前，把「前」目标（+0.13）顶到 +0.06 不可达。 解：B 下沉到 ylim=[−0.15,−0.13]、OFFSET 0.13→0.11 → 前≈−0.03、后≈−0.25，双双落在可达带内。
坑 ② 侧向抓取跨身体失败 → 抓永远用 mover 侧手臂
一度按「目标侧」选臂以避免放置跨身体，反而让抓取跨身体（mover 在右、指令要放左 → 用左臂去抓右侧物体 → 规划失败）。 实测：抓必须同侧才规划得出；而放置只需跨过中线 ~0.11（在双臂包络内）。解：所有方位一律用 mover 侧手臂，左右 oracle 从 50% → 92/100%。
决策 · 单 {D} 族取代 {B}/{C} 路由 hack
filter_instructions 要求模板占位符集合与 episode 完全相等。5 方位都提供 {A} {D} {B} {a} → 一族模板通吃， 方位短语（to the left of / in front of / behind / on top of）注入 {D}，比 v1 的 {B}/{C} 分族更干净。
决策 · 不做 5 路 pair-gate
laptop_verb 有「配对不可演则两局都丢」的 gate；5 方位版每局要试跑 4 个伙伴方位，太贵。 改为用固定留空场景保证 5 方位都可演（B 居中、四侧带全程留空），先不 gate；若量产暴露 scene 特异不可演再补。
