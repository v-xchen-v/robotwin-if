总 · 为什么复刻 + 做成了什么

Instruction Following（IF）能力测试——policy 是不是真按语言指令选动作，而不是退化成「看图做默认动作」（论文称 VLA→VA degradation）——是目前流行 VLA benchmark 普遍不具备的维度。论文提出了这套针对性任务集，但没开源代码。

所以我们的决定：
  1. 快速复刻论文这套 IF 任务集，先在 RoboTwin 2.0 上把可评测任意 policy 的 harness 搭起来；
  2. 再基于此按我们自己的需求打磨修改（强化考核维度、接入我们的评测/训练管线）。

本周产出：5 个任务集完成 4 个（右下四张卡）+ 一套零改上游源码的桥接基建。均达 Layer A（结构）+ Layer B（判定正反例）+ oracle 冒烟 成熟度：

② Operate-Stapler · "mode 枢纽"心智模型的确立

Operate-Stapler

feat-02 · 08-20 · 50c756b

论文维度：共享场景下的动词判别——同一画面，指令动词决定做哪件事。

Raw 出发点 RoboTwin 两个独立原生任务

原生任务原本是什么贡献给我们
press_stapler单臂在原地按下订书机press 专家动作 + press 指令池
move_stapler_pad把订书机搬到彩色垫上move 专家动作 + move 指令池 + 场景采样分布

我们改成 合并同场景 + 动词判别

做的事：把两个原生任务合并进同一场景（订书机+彩色垫+干扰物），用指令里的动词决定做哪件事。垫子在两种指令下角色翻转：press 时是干扰项，move 时是目标。

核心机制：self.mode = seed%2 一处采样、三处读取（建场景/专家/判定）。最重要的结构认知——指令是 mode 的下游投影，不能反推；mode 当唯一枢纽，instruction 和 check 都是它的兄弟投影。这个模型被后 3 个任务复用。

踩坑：self.info 初始化顺序、071_can model_id 不连续、干扰物 glb qpos 只对 stable 物体成立（markpen 无 stable 姿态 → 用 093_brush-pen 顶替）。

③ Operate-Tabletop · 把二选一推广成三选一

Operate-Tabletop

feat-03 · 08-21 · 319bba0

论文维度：恒定桌面上的三选一动词+目标判别。

Raw 出发点 三个原生任务各出一支

原生任务原本是什么贡献给我们
click_bell触碰铃铛顶部中心click 分支 + 指令池（占位符 {A}）
press_stapler按下订书机press 分支 + 指令池（{A}→{B} remap）
adjust_bottle单臂纯拿起（RoboTwin 里唯一单臂 pick）pick 分支 grasp+lift + 指令池（{A}→{C}）

我们改成 三任务合并进恒定桌面 + 三向路由

做的事：把三个原生任务合并进同一恒定桌面场景（铃铛+订书机+可拿物体），做三选一：click / press / pick。画面静止时三模式完全一致，只有指令变。seed%3 + 三个互斥占位符 {A}/{B}/{C} 三向路由，是 Stapler「{B} 有无二分」的自然推广。

诚实的边界：这本质是「三选一 target 选择、动词搭车」，不是真·动词判别——每个物体只有一个 affordance，点名物体动作就定了。要测真·动词判别需给某物体加第二个 affordance（本任务范围外）。
④ Pick-Diverse-Object · 颜色 grounding 的坑最深

Pick-Diverse-Object

feat-04 · 08-24 · 717dbde

论文维度：「颜色+名词」的目标物体 grounding（原生无直接对应，属新建型）。

Raw 出发点 借机制与姿态，不借"只丢瓶子"的窄设定

原生任务原本是什么贡献给我们
adjust_bottle单臂拿起一个瓶子抓取+抬起机制 + orientation-free 指令模板子集（12/4）
pick_dual_bottles双臂各拿一个瓶子瓶子竖立的 resting qpos [0.66,0.66,-0.25,-0.25]

我们改成 12 品类池 + 颜色+名词受控指令

做的事：从"只丢一种瓶子"扩成 12 品类池采 4 个，指令用「颜色+名词」点名 1 个目标（"the blue cup"）单臂拿起，其余 3 个干扰。12 品类等概率目标（seed%12 轮转），颜色贴图眼验锁定 16 变体，逐物体配抓取参数 + 世界系抬起。

最大教训：颜色不能信 MLLM 文本描述——那是噪声文本（单变体主色覆盖 33%–92%），用覆盖率阈值筛颜色会全军覆没。改为渲染真实 baseColor 贴图人眼核校（多材质物体会被中位色洗白，如可乐罐红标+银顶中位成近白）。

还踩了 option A→B（强制混淆项把物体分布压偏）、seed 聚簇（低连续 seed 下 red-shoe 概率异常高，改 seed%N 轮转）、逐物体 resting qpos（phone 通用 qpos 17 次全败 → 换专属 5/5）。

⑤ Place-Relative · 诊断能力的示范

Place-Relative

feat-05 · 08-24 · c547421

论文维度：空间关系理解（beside vs on-top，原生无直接对应，属新建型）。

Raw 出发点 从三个原生任务各借一块（多为局部借用）

原生任务原本是什么借了什么（注意只借局部）
move_can_pot把罐子移到锅旁（非方向性 next to/beside/near）beside 指令池 + 占位符 {B}
stack_blocks_two双臂把两块都搬到中心堆叠只借 on-top 词汇（on top of/atop/onto）；结构不借（它双臂两块，我们单臂 A→B）
place_object_stand把多样物体放到台面上mover 物体池（mouse/stapler/bell/…）+ pre_grasp_dis=0.1 放置机制

（此任务 raw 片段散在三个原生任务、且多为局部借用，故上表说明比单看视频更清楚；需要的话可另跑原生任务补录 raw 视频。）

我们改成 beside/on-top 二元关系 + 场景不泄露关系

做的事：拿起 A、放到 B 的 beside（旁边）或 on top of（上面）。同一套物体池两种关系完全一样，场景不泄露是哪种关系 → policy 只能靠指令关系词判断。beside/on-top 靠占位符签名路由（{B}/{C}），无需写死关系词、保留原生措辞多样性。

诊断示范：首轮 oracle 只有 40%，写诊断逐 seed 打印后发现真因是放置规划失败（不是物理）——B 太偏+跨身体放置。改布局（B 居中/mover 同侧/间距>0.22）后 40%→92%。顺带抓出两个 IF 有效性 bug：beside「空操作蒙对」漏洞、落点砸到已有干扰物。
⑥ Operate-Mic-Drawer · 探针驱动的"搁置判定"

Operate-Mic-Drawer

feat-06 · 08-25 · 搁置

本周唯一没跑通的，但调研本身是高质量的：11 轮 headless 探针，逐字段量状态，隔离出两道相互独立的几何墙。判定为资产不兼容（018_microphone+036_cabinet），非实现失败——env / 指令 JSON / 严格判定器都写好且跑得起来。

墙现象铁证
墙 1 强 arm 轴不可行中央麦克风 → 两臂争中央只开抽屉单臂 ✓；先抓麦克风 → 开抽屉臂规划不到把手（规划器做不了共享中央体积双臂作业）
墙 2 放进抽屉 oracle 极低抽屉垂直净空 < 麦克风+夹爪显式航点把麦克风精确对到抽屉正上方 xy≈0.001，仍下不去（卡在上方 0.13, plan=False）

缩麦克风（最好 3/10）、放大柜子（8/8 抽屉根本没开）、改放置策略全试过顶不住。无视频（探针全 headless），证据是逐字段状态数据。复现脚本已归档：evidence/06-mic-drawer/probe_oracle_check.py。

复活路径：换净空更大的抽屉资产，或大开口铰接容器（microwave/oven），现有 env+判定器+指令池可直接复用。需求高时再回来。
贯穿全周的方法论
  • 指令池全部借 native raw-task 池、不手写——项目既定套路，忠于原生措辞、seen/unseen 隔离在句式模板层。
  • 每任务 Layer A/B 双层验证、探针驱动——不纸面拍板，每个假设用 headless oracle 探针逐字段实测。
  • 反复出现的坑家族：低连续 seed 的首抽聚簇（default_rng(seed).integers 对 seed 0/1/2… 聚簇）——Pick-Diverse、Place-Relative 都踩到，统一改 seed%N 轮转或混合种子流。
  • 反复奏效的原则：「asset 做不到先回 raw task 看它到底怎么做」——高瓶站立、单臂纯拿起、放物体到面上，都是去原生任务里抄对的姿态/机制。
下周主线 · eval/policy（Layer C）

要证明的核心命题：4 个任务真能区分「读指令的 policy」vs「看图做默认动作的 policy」——否则 benchmark 名不副实。

#步骤产出 / 卡点
1先立 baseline 对照，不急着接真实 VLA作弊 oracle（上界 82–98%，已有）vs 瞎猜 dummy（下界应接近 chance：Pick≈1/12、Tabletop≈1/3、Place≈1/2、Stapler≈1/2）。区分度=上界−下界够大才算有效。不需训练，最先能跑出来。
2打通 eval_policy.sh 端到端目前只验过 collect_data。顺带验证 mode 决定性在真实 eval 双 setup 里成立（seed%N 逻辑保证，但未端到端验过）。
3合并评测接入 all_tasks_plus_if.yml4 个任务一次性过评测调度。
4与论文 Table 8 对齐看数值量级是否同一级别（不追逐值还原，论文未开源）。
