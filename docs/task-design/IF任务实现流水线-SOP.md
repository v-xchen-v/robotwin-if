# IF 任务设计与冻结流程

1. 明确要诊断的指令因素，从原生任务中选择模型训练可能覆盖的原子动作；区分训练覆盖、expert 可行与模型实际能力。
2. 用共享场景构造对照，组内只改变被测目标。验证初始 RGB、机器人状态及必要的物体位姿；不同场景间随机化位置和朝向。
3. 用干扰物减少场景与某个原生任务的一一对应，避免引入过大的新操控难度。
4. 根据原生子任务设计 instruction，并检查句式差异是否带来额外因素。
5. 验证 expert、成功判据和反例，例如先错后对、瞬时接触、错误手臂或错误物体；用少量 model eval 确认基础动作可实现。
6. 通过上述可行性检查后，按 expert 资格筛选完整 blocks，固定 seeds；不按模型成败挑选 seeds。
7. 使用固定清单运行公开 checkpoints，保留全部成功、失败、视频、动作和判定证据。
8. 更新设置时标清受影响模式，重新检查资格并重测；其他输出只有在设置未变化时才能复用。
9. 同步代码、seed 清单、成绩、下载备份和视频入口。以 Git commit/tag 固定交付，避免维护多份重复“最新”数据。

研究结论应结合行为轨迹解释二值成功率。例：[大块缩小后仍先抬小块](../attribute-size-6cm-ablation.md)。
