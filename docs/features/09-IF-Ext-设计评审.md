# IF-Ext 七轴指令跟随扩展任务集 — 设计评审稿

> **一句话**：在论文 RoboTwin-IF 的 5 个（多维度耦合）任务之外，新增 7 个**单轴**任务，每个只隔离测一个指令跟随（instruction-following）能力，用来定位一个 policy 到底在**哪个轴上"没听懂指令"**。
>
> 状态：planning · 日期：2026-08-28 · 规模：7 轴 · 本周目标：3 个 · 阅读时长约 8 分钟

---

## 一、为什么这么设计（目的）

论文的 5 个任务把多个能力**耦合**在一起——比如 Operate-Tabletop 里"选摇铃这个动词"就等于"选了铃铛这个物体"，动词和名词绑死。结果就是：policy 失败了，说不清它是**动词没听懂**、还是**物体没认出**。

IF-Ext 反过来做**单轴拆分**：每个任务里，只有一个"指令槽位"是决定成败的变量，其余（几何、可达性、物体身份）全部保持中性。这样一个 policy 跑完 7 个任务，得到的就是它在各轴上的一张**"指令服从率指纹"**——哪个槽位它读了、哪个它无视，一目了然。

被隔离的 7 个轴：

| # | 轴 | 一句话 |
|---|---|---|
| 1 | 动词 verb | 同物体同几何，只有动词变（开 vs 关） |
| 2 | 名词 noun | 跨类别干扰物，只靠类别名词点名 |
| 3 | 形容词 adjective | color > texture > shape 分档，测按需升级 |
| 4 | 左右臂 arm | 物体在双臂重叠区，只靠指令选臂 |
| 5 | 顺序 sequence | 多物体依次入容器，顺序不能错 |
| 6 | 方位 direction | 相对某物体的 左/右/前/后/上 |
| 7 | 抓取接近方向 grasp-approach | 同物体从顶部抓 vs 从侧面抓 |

---

## 二、贯穿所有任务的三条判据（方法）

这是整套设计的核心。一个任务要成立，必须**同时**满足三条——它们既是设计判据，也是可实现性判据：

- **(a) 唯一区分量** — 被测的那个指令槽位，是场景里**唯一**能区分正确动作的信息；其它一切（几何、可达性、物体身份）都保持中性。
- **(b) 双值 oracle ~90%** — oracle 对该槽位的**两个取值都**要能 ~90% 执行。这就是"反例 / Layer B"的基础：只有两个方向都跑得通，"故意做错必判失败"才验证得了。
- **(c) 画面可分** — 两个取值的结果，在相机画面上必须**明显不同**。否则 policy 连当前状态都看不出、成功差异也没有意义，任务对 policy 不可解。

> **这三条不是事后总结，是筛选/淘汰任务的尺子**：
> - `056_switch` 拨杆栽在 (b)(c)——本身成功率低，且开/关画面几乎同一张 → 淘汰。
> - Attribute 的"纹理/大小"档栽在 (a)(c)——构造不出"除一属性外全同"的干扰物，相机也分不清 → 大小砍掉、纹理留但列为最高风险。
> - mic-drawer 式的双臂 Arm-Select 栽在 (b)——双臂同时动作会互撞、几何还会把"用哪只臂"变成冗余 → 改成单臂中央盒子。

**验证方法论**：每个任务都做 Layer A（结构/集成正确）+ Layer B（oracle 正例判 True、反例判 False）。其中 5 个带"故意做错"反例的任务（Verb / Arm / Sequence / Spatial / Grasp）——反例验证是**验收必过项**，不能省略。

## 三、七任务一览（矩阵）

| 任务 | 被测轴 | 指令示例 | 成功判定核心 | 实现风险 | 本周 |
|---|---|---|---|:--:|:--:|
| `if_ext_verb_select` | 动词 | 把它合上 / 打开 | 铰链关节角到达指令方向端 | 中 | ● |
| `if_ext_noun_grounding` | 名词 | 拿起杯子 | 抓取物类别 == 指令名词 | 低 | ○ |
| `if_ext_attribute_ladder` | 形容词 | 拿起红色条纹方形的盒子 | 全部指定属性都匹配 + 分档统计 | 高 | ○ |
| `if_ext_arm_select` | 左右臂 | 用左臂拿起积木 | **哪只夹爪**最终握着（state-based） | 低 | ● |
| `if_ext_sequence_container` | 顺序 | 先红积木、再蓝球、最后绿瓶 | **进入顺序**（轨迹/时间戳） | 中 | ○ |
| `if_ext_spatial_direction` | 方位 | 把 A 放到 B 前面 | 指令轴带符号偏移 + 正交轴锁住 | 低 | ○ |
| `if_ext_grasp_approach` | 抓取方向 | 从顶部 / 侧面拿起方块 | 夹爪 **approach 轴朝向**匹配 | 中 | ● |

● 本周做 ○ 延后。实现风险档来自"时间评估"（判定机制是否已复用/落地）。

## 四、逐任务设计

### 1. IF-Verb-Select — 动词判别 · 风险中 · 本周

- **目的**：动词与物体**解耦**——同物体、同几何，只有动词变。诊断的失败模式是**动词被"物体→惯用动作"先验盖掉**（policy 学到 laptop→开，就无视指令里的"关"）。测法：命令那个**非默认**动词，看它是否真读了动词。
- **场景**：`015_laptop` 开/关。关键——两个变体都从**同一个 ~50% 半开的中间态**起，初始画面**完全相同**，只有指令动词不同，逼 policy 读动词而非靠初始几何猜。（备选：`036_cabinet` 抽屉开/关，更稳但视觉弱；pick-vs-press，最稳但和 Operate-Tabletop 撞。）
- **成功判定**：铰链关节角到达指令方向对应端——开 → qpos 过高阈值；关 → qpos 回低区间。**不是**"关节角发生了变化就算"。
- **反例（Layer B）**：oracle 故意反方向（应关却开）→ qpos 走错端 → 必判失败。
- **风险与待验**：native 只有 `open_*`、没有 `close_*`，**合盖 oracle 要自写**。第一步 spike：从共用中间态**双向**跑，确认开、关都能 ~90%——过了锁 laptop，不过退到 cabinet。

### 2. IF-Noun-Grounding — 目标名词 grounding · 风险低 · 延后

- **目的**：只隔离**名词槽位**——干扰物**跨类别**、被点名类别场景里只有一个，唯一区分量是名词。定位是 Attribute-Ladder 的**对照基线**：连这都挂，说明是最基础的名词 grounding 问题，而非属性优先级问题。
- **场景**：2–3 个**不同类别**物体（杯 / 瓶 / 盒），单臂，纯名词点名。不堆到论文的 4 物体——职责是"对照"，堆物体不按比例换诊断价值。
- **成功判定**：抓取物体类别标签 == 指令名词 且离地过阈值。**不是**"抓到某个东西就算"。
- **反例（Layer B）**：oracle 故意抓一个干扰物（错名词）→ 必判失败。
- **风险与待验**：机制可靠，但依赖多物体抓取池 infra，**当前在 `pick_diverse_object` 分支、不在本分支**（需搬过来或起精简版）。

### 3. IF-Attribute-Ladder — 形容词优先级阶梯 · 风险高 · 延后

- **目的**：验证 policy 是否按"信息量优先级"**只在必要时才升级**修饰词——不是有形容词就用。通过分档干扰物验证它实际用到了哪一层。
- **三档**（大小档已砍，优先级靠后）：
  - **T1**（颜色即可）：干扰物异色 → 只需颜色。
  - **T2**（需颜色+纹理）：存在同色、异纹理的干扰物。
  - **T3**（需颜色+纹理+形状）：存在同色、同纹理、异形状的干扰物。
- **成功判定**：抓取物在**指令给出的全部属性上都匹配** + **分档统计成功率**——T1 高分而 T2/T3 骤降 = policy 没真正用到纹理/形状（退化行为的量化证据）。
- **反例（Layer B）**：抓一个"只满足低档、不满足本档新增属性"的干扰物 → 必判失败。
- **风险与待验**：**全 7 任务里最高**。纹理档双重不确定性——**构造**（~120 物体池能否凑出"同色异纹理""同色同纹理异形"）+ **视觉**（policy 相机能否分辨同色不同纹理，需渲染真实纹理核对）。凑不够则要合成/新增物体描述。

### 4. IF-Arm-Select — 左右臂指定 · 风险低 · 本周

- **目的**：指令指定"用左/右臂"，物体落在**双臂重叠区**、本身无 grounding 歧义。测 policy 是否服从指定臂，而不是用惯用手。
- **场景（三条不变量）**：① 物体放**双臂重叠区**（x≈0）——几何不泄露答案；② **只有被指定臂动作**，另一只闲置（所以没有 mic-drawer 的双臂互撞）；③ 判定是 state-based。资产复用 `handover_block` 的 box（native 已证"中央盒子左右臂都能抓"）。
- **成功判定（state-based）**：盒子离地 **且** 被**指定臂**的夹爪握着、另一只没握。**不能**靠 oracle 自报 ArmTag——policy eval 只能看末态。
- **反例（Layer B）**：oracle 故意用错误的臂完成抓取（即使举起）→ 必判失败。
- **风险与待验**：验一个"盒子固定 x≈0 后，左、右两臂各自都能 ~90%"（对称盒子应直接成立）。

### 5. IF-Sequence-Container — 多物体按序放入容器 · 风险中 · 延后

- **目的**：3 个可命名物体**单臂依次放入同一容器，顺序不能错**。诊断的失败模式：policy 把 3 个都放进去了但**无视顺序**（"顺序盲假阳性"）。
- **场景**：单臂 + **开口容器**（`062_plasticbox` / `110_basket`，开口 → 绕开 mic-drawer 的垂直净空墙）+ 3 个 color+noun 可单独指代的物体。单臂顺序放（双臂会让两个"同时"进容器、破坏顺序定义）。
- **成功判定（轨迹-based，核心）**：逐 step 记录各物体**首次进入容器区域**的时刻，按时刻排序得到实际顺序，与指令顺序逐位比对，**任一相邻颠倒即败**。**绝不能只判"三个都在容器里"**——native `place_cans_plasticbox` 就是只判"都在"、不查顺序，那正是要避开的假阳性。
- **反例（Layer B）**：oracle 故意倒序放（即使三个都在）→ 必判失败。
- **风险与待验**：① oracle 单臂 3 次复合（≈0.9³，靠开口容器+松判定顶高每次）；② eval 能否在 rollout 中**逐 step 采样**物体位置（而非只末尾调一次 check_success）——待查。

### 6. IF-Spatial-Direction — 放置方位 · 风险低 · 延后

- **目的**：在 Place-Relative（已覆盖 左/右/上）基础上**补齐"前/后"**，凑齐 5 种相对方位。方位词是唯一区分量。
- **轴映射**（已由 native `place_a2b_left` 落地）：**左/右 = 带符号 x 轴**；**前/后 = 带符号 y 轴**（新扩展）；**上方 = align**。前/后参考系**以机器人朝向为准**（近机器人 = 前），避免用物体自身朝向（随机化下不稳定）。
- **成功判定**：A 相对 B 在指令轴上的**带符号偏移**过阈值 + **正交轴锁住**（<~0.05）+ 距离落在带内。左右和前后**用不同轴** → 每个方向对必须**分别测反例**（易一个对一个错）。
- **反例（Layer B）**：oracle 放到相反方位（应前却后）→ 必判失败。
- **风险与待验**：world-y 的**哪个符号朝机器人**需跑通确定；前后是相机里的深度差（~0.13m），视觉可分性比左右弱；infra 同 §2 在另一分支需搬。

### 7. IF-Grasp-Approach — 抓取接近方向 · 风险中 · 本周

- **目的**：指令指定**抓取构型**（"从顶部抓" vs "从侧面抓"），同物体两种抓法都可行——动词都是"抓"，唯一区分量是抓法词。测 policy 是否服从指定接近方向，而不是默认用最省力那种。
- **场景**：`create_box` 立方体（复用 §4 的 box，高度可控——调到让侧抓下指清桌面），中央固定。顶抓 = 竖直 -z 接近；侧抓 = 水平接近，各定一组 contact points。
- **成功判定（orientation-based）**：物体离地 **且** 抓取夹爪的 **approach 轴朝向**匹配指令（竖直 vs 水平）。**不是**"抓起来就算"——两种抓法都能举起，只有夹爪朝向能区分。
- **反例（Layer B）**：oracle 用错抓法（该顶却侧）→ 必判失败。
- **风险与待验**：侧抓清桌面 + 朝向判定，spike 验证顶、侧两抓法都能 ~90%。

## 五、范围与排期（一周，含今天 08-28 ～ 09-04）

**现实目标：一周做扎实 3 个**，其余 4 个延后。7 个全做+全验证一周内不现实（每个带 spike/构造风险，4 个还要先搬 infra）。策略：**先打 3 个 spike 退风险，再量产 + Layer A/B 验证。**

- **本周 3 个**：Arm-Select、Grasp-Approach、Verb-Select——都不依赖跨分支 infra、共用 `create_box` 脚手架、各带一个 spike。
- **延后 4 个**：
  - Noun-Grounding、Spatial-Direction —— 机制不难，但先要搬 `pick_diverse_object` / `place_relative` 的 infra。
  - Sequence-Container —— 3 次复合 oracle + eval 逐 step 采样这条可能是坑。
  - Attribute-Ladder —— 纹理档构造 + 视觉，最高风险，可能要新增物体描述。

**实现风险三档**：低（Noun / Arm / Spatial）· 中（Verb / Sequence / Grasp）· 高（Attribute）。
