七轴指令跟随扩展任务集

在论文 5 个多维度耦合任务之外，新增 7 个单轴任务：每个只隔离测一个指令跟随能力，用来定位一个 policy 到底在哪个轴上"没听懂指令"。

状态 planning 日期 2026-08-28 规模 7 轴 本周目标 3 个 Deadline 09-04
一

为什么这么设计

论文的 5 个任务把多个能力耦合在一起——比如 Operate-Tabletop 里"选摇铃这个动词"就等于"选了铃铛这个物体"，动词和名词绑死。结果是：policy 失败了，说不清它是动词没听懂还是物体没认出。

IF-Ext 反过来做单轴拆分：每个任务里只有一个"指令槽位"是决定成败的变量，其余（几何、可达性、物体身份）全部保持中性。这样一个 policy 跑完 7 个任务，得到的就是它在各轴上的一张 "指令服从率指纹"——哪个槽位它读了、哪个它无视，一目了然。

#轴一句话
1动词 verb同物体同几何，只有动词变（开 vs 关）
2名词 noun跨类别干扰物，只靠类别名词点名
3形容词 adjectivecolor > texture > shape 分档，测按需升级
4左右臂 arm物体在双臂重叠区，只靠指令选臂
5顺序 sequence多物体依次入容器，顺序不能错
6方位 direction相对某物体的 左/右/前/后/上
7抓取方向 grasp-approach同物体从顶部抓 vs 从侧面抓
二

贯穿所有任务的三条判据

整套设计的核心。一个任务要成立，必须同时满足三条——它们既是设计判据，也是可实现性判据：

(a)

唯一区分量

被测的那个指令槽位，是场景里唯一能区分正确动作的信息；其它一切（几何、可达性、物体身份）都保持中性。

(b)

双值 oracle ~90%

oracle 对该槽位的两个取值都要能 ~90% 执行。这是"反例 / Layer B"的基础：两个方向都跑得通，"故意做错必判失败"才验证得了。

(c)

画面可分

两个取值的结果，在相机画面上必须明显不同。否则 policy 连当前状态都看不出、成功差异也没意义，任务不可解。

这三条不是事后总结，是筛选/淘汰任务的尺子：
  • 056_switch 拨杆栽在 (b)(c)——本身成功率低、开/关画面几乎同一张 → 淘汰。
  • Attribute 的"纹理/大小"档栽在 (a)(c)——构造不出"除一属性外全同"的干扰物、相机也分不清 → 大小砍掉、纹理留但列为最高风险。
  • mic-drawer 式双臂 Arm-Select 栽在 (b)——双臂同时动作会互撞、几何还会把"用哪只臂"变冗余 → 改成单臂中央盒子。

验证方法论：每任务做 Layer A（结构/集成正确）+ Layer B（oracle 正例判 True、反例判 False）。带"故意做错"反例的 5 个（Verb / Arm / Sequence / Spatial / Grasp）——反例验证是验收必过项。

四

逐任务设计

if_ext_verb_select 实现风险 中 本周

1 · IF-Verb-Select — 动词判别

目的动词与物体解耦：同物体同几何，只有动词变。诊断"动词被物体→惯用动作先验盖掉"（学到 laptop→开就无视"关"）。命令非默认动词，看它是否真读了动词。
场景015_laptop 开/关。两变体都从同一 ~50% 半开中间态起，初始画面完全相同，只有指令动词不同。备选：cabinet 抽屉、pick-vs-press。
判定铰链关节角到达指令方向端（开→过高阈值 / 关→回低区间）。不是"角度变了就算"。
反例oracle 反方向（应关却开）→ qpos 走错端 → 必败。
风险native 无 close_*，合盖 oracle 要自写。先 spike：从中间态双向跑，确认开、关都能 ~90%，不过退 cabinet。
if_ext_noun_grounding 实现风险 低 延后

2 · IF-Noun-Grounding — 目标名词 grounding

目的只隔离名词槽位：干扰物跨类别、被点名类别只有一个。定位是 Attribute-Ladder 的对照基线——连这挂 = 基础 grounding 问题，而非属性优先级问题。
场景2–3 个不同类别物体（杯/瓶/盒），单臂，纯名词点名。不堆到论文的 4 物体——职责是"对照"。
判定抓取物类别标签 == 指令名词 且离地。不是"抓到就算"。
反例oracle 故意抓干扰物（错名词）→ 必败。
风险机制可靠，但依赖多物体抓取池 infra，当前在 pick_diverse_object 分支、不在本分支（需搬）。
if_ext_attribute_ladder 实现风险 高 延后

3 · IF-Attribute-Ladder — 形容词优先级阶梯

目的验证 policy 是否按信息量优先级只在必要时才升级修饰词——不是有形容词就用。分档干扰物看它实际用到哪一层。
三档T1 异色（只需颜色）· T2 同色异纹理（需+纹理）· T3 同色同纹理异形（需+形状）。大小档已砍。
判定抓取物在全部指定属性上都匹配 + 分档统计：T1 高分而 T2/T3 骤降 = 没真正用到细属性（退化的量化证据）。
反例抓"只满足低档、不满足本档新增属性"的干扰物 → 必败。
风险全 7 任务最高。纹理档双重不确定性——构造（~120 池能否凑出"同色异纹理"）+ 视觉（相机能否分辨同色不同纹理）。凑不够则合成/新增物体描述。
if_ext_arm_select 实现风险 低 本周

4 · IF-Arm-Select — 左右臂指定

目的指令指定"用左/右臂"，物体在双臂重叠区、无 grounding 歧义。测是否服从指定臂而非用惯用手。
场景三不变量：① 物体放 x≈0 重叠区（几何不泄露答案）；② 只有被指定臂动作（故无 mic-drawer 互撞）；③ 判定 state-based。复用 handover_block 的 box（native 已证两臂皆可抓）。
判定state-based：盒子离地 且被指定臂夹爪握着、另一只没握。不能自报 ArmTag——policy eval 只能看末态。
反例oracle 用错误的臂完成抓取（即使举起）→ 必败。
风险验"盒子固定 x≈0 后左、右两臂各自都 ~90%"（对称盒子应直接成立）。
if_ext_sequence_container 实现风险 中 延后

5 · IF-Sequence-Container — 多物体按序放入容器

目的3 个可命名物体单臂依次放入同一容器，顺序不能错。诊断"三个都放进去但无视顺序"的假阳性。
场景单臂 + 开口容器（062_plasticbox/110_basket，绕开净空墙）+ 3 个 color+noun 物体。单臂顺序放（双臂会破坏顺序定义）。
判定轨迹-based：逐 step 记录各物体首次进入容器的时刻，排序比对指令顺序，任一相邻颠倒即败。绝不能只判"都在"（native place_cans_plasticbox 的假阳性正是要避开的）。
反例oracle 倒序放（即使都在）→ 必败。
风险① oracle 单臂 3 次复合（≈0.9³，靠开口容器+松判定顶高）；② eval 能否 rollout 中逐 step 采样——待查。
if_ext_spatial_direction 实现风险 低 延后

6 · IF-Spatial-Direction — 放置方位

目的在 Place-Relative（左/右/上）基础上补齐"前/后"，凑齐 5 方位。方位词是唯一区分量。
轴映射左/右 = 带符号 x 轴（native place_a2b_left 落地）；前/后 = 带符号 y 轴（新增）；上 = align。前/后参考系以机器人朝向为准（近=前），避免用物体自身朝向。
判定指令轴带符号偏移过阈值 + 正交轴锁住 + 距离带内。左右和前后用不同轴 → 每个方向对分别测反例（易一对一错）。
反例oracle 放到相反方位（应前却后）→ 必败。
风险world-y 哪个符号朝机器人需跑通确定；前后是深度差(~0.13m)、视觉比左右弱；infra 同 §2 在另一分支需搬。
if_ext_grasp_approach 实现风险 中 本周

7 · IF-Grasp-Approach — 抓取接近方向

目的指令指定抓取构型（从顶部 vs 从侧面），同物体两种抓法都可行——动词都是"抓"，唯一区分量是抓法词。测是否服从而非用最省力抓法。
场景create_box 立方体（复用 §4 的 box，高度可控让侧抓清桌面），中央固定。顶抓 = 竖直 -z 接近；侧抓 = 水平接近。
判定orientation-based：物体离地 且 夹爪 approach 轴朝向匹配（竖直 vs 水平）。两种都能举起，只有朝向能区分。
反例oracle 用错抓法（该顶却侧）→ 必败。
风险侧抓清桌面 + 朝向判定，spike 验证顶、侧两抓法都 ~90%。

范围与排期（一周 08-28 ～ 09-04）

现实目标：一周做扎实 3 个，其余 4 个延后。7 个全做+全验证一周内不现实（每个带 spike/构造风险，4 个还要先搬 infra）。策略：先打 3 个 spike 退风险，再量产 + Layer A/B 验证。

本周 3 个

  • Arm-Select — 中央盒子，验两臂各自 ~90%
  • Grasp-Approach — 复用同一 box，验侧抓清桌面
  • Verb-Select — laptop 合盖 oracle 自写，双向 spike

共用 create_box 脚手架，不依赖跨分支 infra。

延后 4 个

  • Noun / Spatial — 机制不难，先搬 pool / place-relative infra
  • Sequence — 3 次复合 + eval 逐 step 采样可能是坑
  • Attribute — 纹理档构造+视觉，最高风险

杠杆：3 个 spike 都快过 → 可冲第 4 个 Noun。
