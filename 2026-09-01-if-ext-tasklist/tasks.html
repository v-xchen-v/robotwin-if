IF-Ext — 单轴指令跟随任务集

论文 RoboTwin-IF 的 5 个任务集是「任务内混合多维度」；IF-Ext 反过来做单维度拆分——每个任务只隔离测一个能力轴，方便定位 policy 具体在哪个轴上退化。同一场景成对生成（相邻种子像素同帧、只有指令变），使命名槽位成为唯一区分量。

IF-Verb-Select · 轴 1

Verb-Select — pick vs shake

tasks/envs/bottle_verb.py
就绪

核心：同一个瓶子、同一套几何，只有指令里的动词变。诊断的失败模式是动词被「物体→惯用动作」先验盖掉（policy 学到 bottle→拿起，就无视「摇」）。两个动词都是 001_bottle 的 native 动作 → 都在能力库内，不会塌成 OOD。

唯一信号
指令动词 {V}（pick-族 / shake-族）
成功判据
做出被命令的动作：pick = 瓶子离地过阈值；shake = 末端往复振荡。非「碰到瓶子就算」
反例(Layer B)
该 pick 却 shake / 该 shake 却 pick → 必判失败
IF-Noun-Grounding · 轴 2

Noun-Grounding — 纯名词 grounding（对照基线）

复用 pick_diverse_object（去形容词 + 干扰物改跨类别）
计划·复用

核心：唯一区分量是类别名词，干扰物是不同类别。它是 Attribute-Select 的对照基线——policy 连这都挂，说明是最基础的名词 grounding 问题，而非「用不上视觉特征」。价值是比较性的。直接复用原 pick_diverse_object 的物体池与抓取参数。

↑ 每局点名一个类别、其余同框物体是跨类别干扰物；clip 取自复用的 pick_diverse_object 基座（现成物体池 + 抓取参数）。

唯一信号
类别名词 {A}；干扰物必须跨类别、被点名类别场景里只有一个
成功判据
抓取物类别标签 == 指令名词 且离地过阈值。非「抓到东西就算」
反例(Layer B)
oracle 故意抓干扰物（错名词）→ 必判失败
IF-Attribute-Select · 轴 3

Attribute-Select — 单一视觉特征 grounding（4 mode）

tasks/envs/attribute_select.py
开发中

核心：物体其余特征全固定，只有一种视觉特征是区分量。按特征型分 4 个独立 mode，分 mode 统计成功率：某 mode 骤降 = policy 用不上那一类特征。全部用 primitive（create_box/sphere/cylinder）生成，特征是写死的、不用反推 → 自包含。

唯一信号
形容词短语 {ADJ}；seed%4 定 mode（color/decal/shape/size）、seed//4 定场景
成功判据
抓取物在当前 mode 特征上匹配目标；分 mode 报成功率 + value-0/1 gap
反例(Layer B)
每 mode 分别测：抓「本特征不匹配、其余全对」的干扰物 → 必判失败
IF-Arm-Select · 轴 4

Arm-Select — 左臂 vs 右臂

tasks/envs/arm_select.py
完成 · N=15 各 100%

核心：指令显式指定「用左臂/右臂」，物体落在双臂重叠区、固定 x=0（几何完全不泄露答案）。测 policy 是否服从指定臂，而不是「哪只手方便用哪只 / 总用惯用手」。臂词是唯一区分量。

唯一信号
臂词 {a}（the left / right arm）
成功判据
state-based：末态盒子离指定臂 TCP 更近（实测 0.14 vs 0.51）且离地。非 oracle 自报臂
反例(Layer B)
指令左臂、强制右臂执行 → 0/15 全判失败
IF-Sequence · 轴 5

Sequence — 按指令顺序堆叠

tasks/envs/stack_sequence.py
完成

核心：三块彩色积木堆成一塔，bottom→top 顺序由指令给定；填顺序槽位的颜色每局都变，所以顺序词是唯一信号。诊断的失败模式：policy 把三块都堆上去了但无视顺序（「顺序盲假阳性」）。

唯一信号
指令给的 bottom→middle→top 顺序（{A}/{B}/{C} 是位置，非固定颜色）
成功判据
轨迹/时间戳-based：按「首次到位」先后排序须逐位匹配；任一相邻颠倒即 fail。非「三块都在塔里就算」
反例(Layer B)
oracle 故意倒序堆 → 即使最终成塔也必判失败
IF-Spatial-Direction · 轴 6

Spatial-Direction — 放置方位（5 值）

tasks/envs/place_relative.py
完成

核心：把 mover A 放到 reference B 的指定方位；同一物理场景可容纳全部 5 个方位，锚点/被放物固定，只有方位词决定正确落点。左右=带符号 x 轴、前后=带符号 y 轴（以机器人朝向为准）、上方=z/align。下面 5 段是同一 mouse+coffee-box 场景。

唯一信号
方位词 {D}（left / right / front / back / on top）
成功判据
指令轴上带符号偏移过阈值 + 正交轴锁住（<0.05）+ 距离落带内。左右/前后分轴
反例(Layer B)
放到相反方位 → 必判失败；左右、前后分开测（不同轴，极易一对一错）
IF-Grasp-Approach · 轴 7

Grasp-Approach — 顶部抓 vs 侧面抓

tasks/envs/grasp_cube_approach.py
完成 · top/side 各 100%

核心：物体固定、同一初始位姿，动词都是「抓」，唯一区分量是抓法词（从顶部 / 从侧面）。测 policy 是否服从指定接近方向，而不是默认用自己最省力的抓法。两种抓法末态夹爪朝向一眼可分。

唯一信号
接近方向短语 {D}（top-族 / side-族）
成功判据
orientation-based：离地 + 夹爪 approach 轴匹配（竖直 vs 水平，角度阈值卡）。非「抓起就算」
反例(Layer B)
用错抓法（该顶却侧）→ 即使举起也必判失败

Verb-Select 早期版

laptop open / close

tasks/envs/laptop_verb.py
备选 / 受限

015_laptop 开/关，从 50% 共用中间态起验，N=20 开/关各 90%（可靠子集变体 {1,9}）。已被 bottle_verb 取代为 Verb-Select 主版：close 是全 native 里唯一没演示过的闭合动作 → 对 zeroshot/native-ft 是 action-OOD，二值判据下 close=0 无法归因（「没读动词」vs「执行不出」）。仅 ifext-ft 协议下有效。

共用设计（评审要点）

同场景成对生成 —— 单轴隔离的结构性保证

scene_seed = seed // k 定场景、mode = MODES[seed % k] 定该轴取值 → 相邻种子对是同一物理场景（同变体/位姿），只有指令不同。评测跑连续种子即拿到像素同帧、仅指令变的对照局。这直接落实「单轴对照对必须同场景」——物体位置若与答案相关，policy 不读指令也能刷满分。

成功判据都对准「被测轴」，拒绝末态假阳性

  • 动词类看动作是否发生（pick/shake、开/关方向），不看「碰到物体」。
  • 臂 / 接近方向看末态 state / 夹爪朝向，不信 oracle 自报。
  • 序列看轨迹时间戳，不看最后一帧（末态编码不了顺序）。
  • 方位看带符号偏移 + 正交轴锁定，左右 / 前后分轴测反例。

被测行为须在能力库内（避免塌成 OOD）

IF 诊断的前提是被测行为对模型可执行；否则二值判据下失败无法归因，IF 塌成 OOD 泛化。Arm / Grasp / Sequence / Spatial / bottle-Verb 均为 native 能力库内行为；laptop close 是例外（见上「备选 / 受限」）。
